# WxBCH Public Pool

A **Public-Pool-style Bitcoin Cash solo mining pool for BCHN-compatible nodes**.

This repository is a clean-room implementation inspired by the architecture and operator workflow of [Public Pool](https://github.com/benjamin-wilson/public-pool). The upstream Public Pool project is GPL-3.0; this project is also GPL-3.0.

## What it provides

- Stratum V1 for SHA-256 ASIC miners
- BCHN-compatible JSON-RPC via `getblocktemplate`
- BCH CashAddress and legacy address validation
- Per-miner coinbase payout address
- Solo mining: a valid block is submitted directly to your BCHN node
- ZMQ `hashblock` support for fast new-job notification
- Variable difficulty (vardiff)
- Version rolling / ASICBoost-compatible version mask negotiation
- Persistent SQLite share and block records
- Per-worker accepted/rejected share statistics
- Current template API
- Lightweight browser dashboard
- Docker and Docker Compose
- Designed for Umbrel and self-hosted BCHN nodes

## Architecture

```
SHA-256 ASIC
    |
    | Stratum V1 :3336
    v
WxBCH Public Pool
    |             \
    | RPC :8432    \ ZMQ hashblock :8433
    v               v
BCHN / AxeBCH node
    |
    | submitblock
    v
Bitcoin Cash network
```

The pool does **not** hold BCH and does not implement payouts. In solo mode the miner's BCH address is placed directly into the coinbase transaction generated by the pool.

## BCHN node requirements

The node must:

1. Be fully synced.
2. Be able to answer `getblocktemplate`.
3. Allow RPC access from the pool container.
4. Publish ZMQ `hashblock` if you want immediate job refreshes.
5. Run with mining/RPC access enabled.

Example BCHN configuration (adjust for your installation):

```ini
server=1
rpcuser=YOUR_RPC_USER
rpcpassword=YOUR_RPC_PASSWORD
rpcbind=0.0.0.0
rpcallowip=172.16.0.0/12
zmqpubhashblock=tcp://0.0.0.0:8433
```

Do not expose the RPC port or RPC credentials to the public Internet.

## Configure

```bash
cp .env.example .env

```

Set at minimum:

```env
RPC_URL=http://YOUR_BCHN_HOST:8332
RPC_USER=YOUR_RPC_USER
RPC_PASSWORD=YOUR_RPC_PASSWORD
ZMQ_HASHBLOCK=tcp://YOUR_BCHN_HOST:28332
```

## Miner configuration

Use the BCH payout address as the Stratum username.

```
URL:      stratum+tcp://YOUR_POOL_IP:3336
Username: bitcoincash:qYOUR_BCH_ADDRESS.worker1
Password: x
```

Legacy BCH addresses are accepted where BCHN/Libauth can decode them.

For a second worker:

```
Username: bitcoincash:qYOUR_BCH_ADDRESS.worker2
```

The part before the first `.` is the payout address. The suffix is the worker name.

## Difficulty

The default starting difficulty is `8192`. This is intentionally much higher than Bitcoin difficulty-1 so normal ASICs do not flood the pool with shares.

Vardiff targets approximately:

```
TARGET_SHARE_SECONDS=30
```

Adjust the initial/min/max values in `.env` for your miner fleet.

## Version rolling / ASICBoost

The server advertises Stratum V1 version rolling and accepts changes inside:

```env
VERSION_ROLLING_MASK=1fffe000
```

The submitted version must preserve all bits outside the configured mask.

## Important safety checks

The pool:

- validates the payout address before authorization;
- validates share difficulty against the miner's assigned target;
- validates version rolling against the configured mask;
- rejects stale jobs;
- submits a candidate block only after it meets the BCHN network target;
- records accepted and rejected shares;
- persists block submission status.

Always verify the payout address configured on a miner before pointing production hashpower at a new pool.

## API

### `GET /api/pool`

Returns pool-wide status and worker statistics.

### `GET /api/miners`

Returns all workers currently known by the pool.

### `GET /api/miner/<address>`

Returns workers for one BCH address.

### `GET /api/template/current`

Returns the current BCHN template summary.

### `GET /health`

Returns a basic health status.

## Data

SQLite is stored at:

```
/data/pool.sqlite
```

The Docker Compose file persists it in the `pool-data` volume.

## Status

This is the initial BCHN implementation. Before opening it to public hashpower, test it against BCHN regtest/testnet and then a real synced mainnet node. In particular, validate Stratum byte order, coinbase construction, CashAddress decoding, share validation, and block submission with your exact BCHN release and miner firmware.
